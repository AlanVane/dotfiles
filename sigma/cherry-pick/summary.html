关键成果

  • 粒度尺子：merge/rebase = 整支，cherry-pick = 单个/少数
  • 配方模型：改动 = 源侧（commit − 父）比出，盖章在目标顶端（新父）
  • 空提交网：改动已在 → 拒绝拍；两个洞（被 revert / 周围代码变了）
  • 范围语法：A..B = 减法、天生不含左端；左端要包含就退一格 A^..B
  • 两态流程实测走通：撞 → 编辑删标记 → add → --continue
  • 三路本质表：merge 加法整支 / rebase 改写整支 / cherry-pick 加法单个
  • cherry-pick 安全因只做加法（不改写不删已有），团队拉取无碍
  • 防重复靠摘前查账：git log --grep 搜目标分支的消息

教法更正（1 处，如实记录）

  • 「cherry-pick 必出新编号」不准确：SHA 是 tree+parent+author+committer+message 五要素哈希——父相同 + 同秒提交时会复现原 SHA（受控实验 sleep 2s 才变）；更正为「几乎总是新编号，因为父/时间通常不同」
