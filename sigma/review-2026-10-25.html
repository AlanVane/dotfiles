🏁 头号事件：「一包文件」第三次换形通过，关口关闭

换形题：普通 clone 之后，awesome-ui/ 目录里有什么？
押 C（目录存在但空），推理链自己走完：「clone 时主仓库有了地址与挂载名，还没取回子模块对象库，也没有释放工作区」。 
ls awesome-ui/          → 空目录
git submodule status    → -a936c14... awesome-ui
cat .gitmodules         → path + url（无内容）
git cat-file -t a936c14 → 致命错误：Not a valid object name
收尾自述：「原以为是完整仓库，实际只是地址与挂载名」 → 补上末格「还有钦定 SHA 便签」。
10-22 首押 ✗、10-23 二押 ✗、10-25 三押 ✓ + 自述病根 → resolved。

⚠️ 今日最大风险：add 会把便签「降级」

布景：index 钦定 553b8d1，子仓库 HEAD 被 checkout 回 a936c14，status 显 M awesome-ui。
问第一动作 → 答「不知道判断逻辑」→ 三格梯子（X..Y 定义 → 方向 → 命令）走通，判对「落后」+ 敲对 submodule update。
押「直接 add 会怎样」→ A ✓。副本实测： 
add 前便签: 553b8d1
add 后便签: a936c14      ← 静默降级
主仓库 status: 0 行改动
同事按新便签 update → 落到 v2「新增按钮组件」
落规则：见 gitlink M 先比两个 SHA —— 超前 = 两层提交 / 落后 = submodule update，绝不 add。
