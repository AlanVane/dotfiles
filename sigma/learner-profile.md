# Learner Profile

Updated: 2026-10-29

## Learning Style

- Preferred explanation mode: concrete examples（scratch repo 实测最能落地；抽象机制问题常答「不知道」，需梯子降阶到具体场景）
- Pace: moderate — 识别类问题快，机制复述类问题需要时间，多次「不知道」后经降阶梯子可完成推理
- Responds best to: 反例实验 + 预测问题（先预测再实测，矛盾驱动模型更新）；梯子末格填空（worked example 留最后一步）——填空梯子在 git-rebase、远程协作课再次验证有效
- Struggles with: 无提示地复述机制；新场景预测（模型未内化时会退回旧误解）；**长会话尾段（疲劳）押注纪律崩塌**——多连问（4 个嵌套押注）会直接混乱，**一次只问一步**才恢复（10-17 教法侧事故记档）
- 优点：细节复述准确（SHA、命令全名、行号都能精确引用）；**抓错能力**（10-14 抓到老师手写账本矛盾）；**读原文自纠**（10-17 对照 git 提示原文当场纠出 merge→rebase）

## Misconception Patterns

- 未验证时倾向凭直觉猜 git 的结果，且偏向「危险/否定」方向（git-aliases、git-rebase、10-10、10-14 hard reset）——**10-17 复习自查通过**（「对象还在库，只是 log 看不到」），该实例销账；模式本身仍需押注把关；**10-19 新例**：cherry-pick 重复摘猜「会被拒绝」（实为空提交网停住），实测后一步自解；**10-20 worktree 课 3 连发**（同分支两处签出猜「直接成功」→「提交失败」→尸登记猜「不用管」）——反向也猜（不只猜「危险」，也猜「git 会保护/自愈」），**共同病根 = 押注前不建模型**：对策不变，押注题强制先说推理链再落选项；**10-25/26 复习清偿又 3 连发**（worktree 删目录押「对象跟着没了」/ 只推子仓库押「便签自动跟随」/ detached 押「提交被拒绝」），全部实测击破——第三例坐实二分直觉：**要么当 git 是门卫（会拦），要么当它会自愈**；**10-25 新增镜像病根**：误解 #5「gitlink 便签写的 SHA 在主仓库对象库」= **「账上写着 = 东西在我这儿」**，与 10-20「看不到 = 不存在」互为镜像——两边都是把账本当实物；误解 #3（两层 SHA 混淆）销账次日即以此形态复发，**「SHA 分层」须按天复测直到两次间隔通过**；**10-26 白天：gitlink「账上有号码」第 2 次复发**（押 `cat-file -t` 在主仓库能查到 → 实测致命错误、子仓库才认），且当日两次填空都滑回实物层（引用死了→填 `refs/heads/main`；prune 清登记→填「commit 对象」）——**「账本 vs 实物」仍是最强主病灶，凡「账上写着」处先问「东西在哪」**
- 模型复述正确 ≠ 已内化：正确复述后新场景仍触发旧误解（git-aliases #4、git-rebase #1 三连发）——**rebase「原样搬运」为最强复发型个案**：10-17 连胜 2/2 销账，**10-18 销账次日第 3 次复发**（「原 C、D 挂 E 后面」）→ 对策：销账后 1d 仍须押注一把；**自我抓矛盾**（10-14 抓老师账本、10-18 被指两格矛盾后秒自纠）是最快纠错通道，优先用
- **收尾命令混入**（rebase 停车写 merge 的 commit/continue）——四次复发：10-10、10-13 纠、10-17 晨低载复习首过、10-17 综合现场（疲劳 + 提示原文在屏上）再复发 + 过度纠正 → 对策：**停车第一件事 = 逐字读 git 提示，命令以提示为准，不调记忆**——**10-18 综合独立补考（零提示、原文在屏）终验通过 + 纪律自陈完成，本条收官**
- **两层故障混淆**（10-17 新增）：把「快进校验失败」（账不齐、文件层无事）当「冲突停车」（文件等裁决）——**10-18 独立补考两层辨析自己说出，销账**
- 表述混淆：机制说对但措辞/归因错位，或标签代答（「走 merge 那套」代替结局预测；填空把标签填进要地点的空）——反问澄清/重问即可纠（10-17 两次重问均过）；答「不知道」后要**留格**才落地
- 答题时倾向跳过「为什么/半问」直接给操作方案——**10-17 加重到整段跳押注 ×3**；点名追问仍屡试不爽，但疲劳段须配合**一次只问一步**——**10-23 submodule 课再现 ×3**（押注跳落、两问答一、配对只答一个词）：点名追问均补齐，但「一次只问一步」是 10-23 教学主力
- **普通文件反射迁移到 gitlink**（10-23 新增）：`M awesome-ui` 一出就条件反射 `add + commit`，不先判断方向——靠反证链（子仓库内部「无文件要提交，工作区干净」却仍被 add 把便签改写）才拆除「add = 记录本地修改」模型；**伴生「两层 SHA 混淆」**：把主仓库自己的提交 SHA 当成 gitlink 便签的值。对策：见到 gitlink 先比对两个 SHA（index 钦定 vs 工作区实际）再动手；**10-25 实测补丁：方向判据已成型**——`X..Y` 定义（Y 有 X 没有）→ 超前=两层提交 / 落后=`submodule update`，且副本实测「add 会把便签静默降级」（553b8d1→a936c14、status 干净）已作为反例存证；但**判据是梯子扶着走完的**，独立复述待验
- **「账本/实物」族谱 10-27/29 再添两形态（同一病根：把「记账」「走位」当实物、当静止）**：①**依赖链幻觉**（误解 #8）——以为主仓库 push 得等子仓库先推，反演题押「同事拿不到主仓库的新 commit」✗；实测主仓库账照推照拉，撞墙在 `update` 取对象（not our ref / exit 128）→ 靠「便签只是一串字符串」三空收口。②**锚点幻觉**——押「gc 不会清，因为 detached HEAD 指着它」，结论蒙对依据错：HEAD 早被 `update` 挪回钦定 SHA；真正的保命者是 reflog（90 天）+ 分支/标签。对策：凡出现「谁指着它 / 谁等谁」先问**「它现在还在那个位置吗」**；**10-30 依赖链第 2 次复发**（主仓库 push 押「推不动、应先推 ui」✗，实测 exit=0 直接推上去）——同轮被追问「commit 里存了什么」立刻答「只有 SHA 字符串」，机制在、押注不在：**首答与机制层已分离**，对策固定为「先答账在哪本、再落选项」
- 课堂结论若以「必/绝不」表述，他会长期当硬规则记——**教法侧风险**（10-11 实测推翻）——讲机制时默认留例外

## Metacognition

- Self-assessment accuracy: well-calibrated 为主（git-aliases + git-rebase 多次一致）；occasional 偏高（cherry-pick 6/7）；10-15 首次偏低；**10-17 恢复准确**（远程协作自评「基本掌握」= rubric：单点全过、综合卡壳）；**10-23 诊断性自评准确且带信息量**（概念 2 自评「Lost」→ 复述实测 2 对 1 忘 1 岔——他能预判自己「跟着问能答 ≠ 自己能讲」的短板，自评可直接采信）；**10-23 概念 3 自评首次偏低**（自评「基本会」，rubric 85% 过关 + 换形一次命中）——给具体证据即可校准，勿过度安慰；**10-23 收官日两点**：概念 4 自评「基本会」= rubric 80% 准；概念 5 自评「Solid 扎实」略偏高（rubric 85%，why 踩梯子、收口句糊）——**「Solid」出现时须摆证据校准，不照收**；**10-27/29：又出现「结论蒙对、依据全错」**（gc 题押「detached HEAD 指着它」——锚点幻觉；同期反演题直接押错方向）→ 判分只看推理链，不采信结论；**10-25：「不知道判断逻辑」直说 → 三格梯子即通**（诚实报缺口比硬猜省轮次）；押注仍常只回一个字母（A），推理链须点名催；**10-30：押注首答 ×2 翻车（「会报错」门卫直觉 /「推不动」依赖链）但机制题全中**——不是不懂，是落选项前不建模；**判分仍按押注判，不按事后解释判**
- Fluency illusion frequency: occasional — 10-17 出现实例（自评「fetch/pull 我会」、机制答成「更新工作目录」）——靠反例实验当场击破；**10-19 换形复发第 2 次**（答「fetch 会更新当前分支」→ 双克隆实测击破、病根自陈「混淆 origin/work 与 work」）→ **10-20 换形再押通过（status 落后归因自己说出），关口关闭，间隔→2d**
- 间隔复习健康：10-10 清 12 项复习债全过；10-17 清 5 组债；10-18 独立补考 3 专项 + 15 项债；**10-19 到期债 19/19 全清（三批，2 起换形复发均实测击破）**；**10-22 四笔债全清（rebase 押②销账 + 判据复述过 + worktree 换形 2/2 + fetch 再验带瑕疵）**；**10-23 两笔清（submodule 概念 1 复习过 1d→2d + 误解#2 换形通过关口关闭）+ 概念 3、4、5 三日连开全通关，git submodule 全课 5/5 收官**；**10-24 夜→10-25 凌晨清偿 3 笔**（fetch ✓ 2d→4d / submodule 2 ◐ 维持 1d / submodule 3 ✓ 1d→2d），**误解 #1 第三次换形通过、关口关闭**；**10-25→26 清偿 5 笔（3 笔押注翻车）**：worktree 概念 1-3（2 过、概念 1 复发重置 1d）、submodule 概念 4-5（双押错、均重置 1d）；新沙盘 `/tmp/opencode/two-layer`（只推子仓库留证）、`/tmp/opencode/wt-review`（删 worktree 留证）。**10-26 白天清偿 4 笔**：worktree 1 ✓（1d→2d，误解 #2 关口关闭）、worktree 2 ✓✓ 换形（2d→4d）、worktree 3 ◐（维持 2d——prune/remove/锁判据都对，但 `git worktree lock` 是**备课漏账**、当日补讲=讲解所得）、submodule 2 ✗（结论对、依据押回「账上有号码=东西在这儿」，维持 1d）。**新日程：10-27 submodule 2 重测 + 4/5、10-28 worktree 1/3 + lock 换形 + fetch、10-30 worktree 2 + rebase 判据 8d 复验**。**10-30 全清 4/4**（概念 1 ✓ 4d→8d、3 ◐ 1d、4 ◐ 1d、5 ✓ 1d→2d）：两笔翻车都是押注首答，机制追问零梯子即中；概念 1 正反面双问全过（「不共享对象库」/「只改 index 里的 SHA」）
