收官日（概念 4-5）亮点

  • 「M 的本质」自己推出来了：主仓库不碰源文件、只比对两个 SHA——ls-files -s 推理链完整（便签 a936c14 vs 顶端 7b9c5f4）
  • 主动说出推送顺序：「子仓库先 push」——而且能说清为什么报错对团队是好事（git 不替用户做决策、不掩盖问题）
  • 两层全流程独立敲完：card.js 从子仓库 commit 到同事 clone 验证，唯一提醒点是第二层（主仓库 add+commit）
  • detached HEAD 三格梯子收口：假脏场景预测正确，落到「停下即干净」的保证
  • 移除四刀分工零混淆：deinit 清配置 / git rm 销账本 / rm -rf 清对象库 / commit 记账——辨析题两边全对
  • re-add 对称练习：从「不知道 add 命令」到填空推出 git submodule add <url> <path>，全新 clone 同事侧一次到位

误解记档（4 起）

  • 「子模块登记 = 一包文件」active · 换形两连不过，10-25 需第三次
  • 「status 没显示 SHA → 账变了」（摘要当账本读）10-23 换形通过 · 关闭
  • 「M awesome-ui 一律 add+commit 修」（gitlink 当普通文件）10-23 反证链 + 换形销账
  • 「update 拿不到钦定 SHA 会静默退回旧版本」10-23 实测硬报错击破 · 销账

遗留尾巴（记入复习债）

  • 「两层」是最大风险点：概念 4 练习时推完子仓库就停，主仓库层要提醒——两层提交流的肌肉记忆要单独固化
  • 「Solid」自评存疑：概念 5 硬题全对，但 detached 的 why 是梯子扶着走完、收口句表述糊（分支浮动/SHA 钉死没说准）
  • 方向判断尾巴：见到 gitlink 先比对两个 SHA 再动手，别让普通文件反射先跑
  • 160000「钦定便签」独立复述：10-25 复测
  • 命令标签召回弱：submodule add 当场不知——靠拆字 + 读提示原文纠的路子继续用
