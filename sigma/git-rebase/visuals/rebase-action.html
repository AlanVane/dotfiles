rebase 的动作：前后对比

场景：base 上有 A → B，topic 从 B 分出来，你在 topic 上拍了 C → D 两张照片。之后 base 上来了新照片 E。你站在 topic 上跑 rebase。

rebase 之前
两条线，C/D 的父链经过 B（旧的起点）
rebase 之后
一条线，C'/D' 是重新拍的新照片

rebase 做了三步，你始终没挪脚

1
把 topic 上 C、D 的改动拿出来（C 改了什么、D 改了什么）
2
在 E 的基础上重新拍两张照片 C' → D'——内容一样，但照片全新（编号/SHA 变了），父链接在 E 后面
3
把 topic 便利贴贴到 D' 上——你不挪脚、topic 分支不被删除。切换到别的分支是 merge/tmg 才做的事
对照检查你的两个猜测
  • 「rebase 后没有 topic 分支了」——错：topic 便利贴只是换到新照片上，分支还在
  • 「rebase 后切到基线分支」——错：rebase 不挪脚；切分支是 tmg（merge）才做的
  • 你站在 topic 上跑 rebase，跑完还在 topic 上，git log 看到一条线：A → B → E → C' → D'
