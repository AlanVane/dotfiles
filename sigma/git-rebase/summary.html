关键成果

  • 核心模型：rebase = 复制重放（重新拍照片），commit 不可变、SHA 必变
  • merge vs rebase 两把尺子：merge 加照片（历史只增、永不静默丢）、rebase 换照片（改写历史）
  • 冲突两态规则实战走通：逐张撞 → 标记 → add + --continue → 一条线
  • 交互式 rebase 实操：squash 整理历史，3 张变 2 张
  • 危险面物理模型：远程照片墙——push=复印上墙、rebase 后 push 被拒、--force=撕墙换照片
  • 黄金法则落地：别人可能拉取的分支不要 rebase；topic 只你一人用 = 敢 rebase
  • 工作流集成：rebase 两个插入口——①开发中跟上最新 base（隐患前置）②tmg 前整理历史

拆除的误解（4 个，全部解决）

  • 「rebase 把 commit 原样搬运」→ 不可变 + 父指针 → 只能重新拍
  • 「rebase 后 topic 分支没了」→ 分支便利贴还在，只是换了贴的位置
  • 「main 历史里也能看到 C'/D'」→ log 从便利贴往回走，没合并就看不到
  • 「已 push = git 接受过，所以可以 rebase」→ 因果反了：已 push = 远程有旧副本 → 撕墙需 --force、有受害者就不能动
