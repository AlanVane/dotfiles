## Misconceptions

| #   | Concept                   | Misconception                          | Root Cause                                                                        | Status   | Counter-Example Used                                                    |
| --- | ------------------------- | -------------------------------------- | --------------------------------------------------------------------------------- | -------- | ----------------------------------------------------------------------- |
| 1   | rebase 的动作（复制重放） | 「rebase 把原 commit 原样搬运」        | 不知道 commit 对象不可变（父指针固定），未意识到接新 base 需改父链                | resolved | 问题 9 修正（重新拍+SHA 不同）+ 问题 10 复述 WHY（commit 不能改）       |
| 2   | rebase 的动作（复制重放） | 「rebase 后 topic 分支没了/切到 base」 | 把 tmg 的行为（切过去+撕标签）套到 rebase；便利贴模型未连线                       | resolved | 对比图讲解 + 复述三点全对（分支还在、站 topic、一条线）                 |
| 3   | rebase 的动作（复制重放） | 「main 历史里也能看到 C'/D'」          | 把「历史是一条线」误解成「所有分支共享同一完整历史」；不知 git log 从便利贴往回走 | resolved | 图讲解 + 复述三点全对 + main 看不到 C'/D'（没合并、log 从便利贴往回走） |
| 4   | rebase 的危险面（改写历史） | 「已 push 过 = git 已接受过版本，所以可以 rebase」 | 因果反了：把「已推送」当成安全证明；实际已推送 = 远程留有旧副本，rebase 后 push 会被拒、需 --force 覆盖，危险随 push 增加而非减少 | resolved | 讲解照片墙模型 + 学习者自纠「方向反了：push 过=远程有旧副本→push 被拒」+ 场景 3 vs 4 区分（拒绝看墙上旧副本、force 安全看有无复印件）通过 |
