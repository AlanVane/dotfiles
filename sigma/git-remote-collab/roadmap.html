01远程库模型（origin、两本账）

✓ 85%

clone / remote add 之后，本地同时对着两个库：自己的 + 远程的副本账本。

02远程跟踪分支（origin/main 快照便签）

✓ 90%

origin/main 是「上次通讯时远程的样子」，不随你本地 commit 动。

03fetch vs pull

✓ 90%

fetch = 只抄账不动手；pull = fetch + 合并到当前分支。

04push 与追踪关系（-u、branch -vv）

✓ 90%

本地分支 ↔ 远程分支的连线：谁跟谁、落后多少、默认推去哪。

05同步中的冲突（pull 撞冲突）

✓ 85%

pull 也会停车——现场和收尾全是你已会的 merge 那套。

06push 被拒与落后处理

✓ 85%

fetch → 整合 → 再 push 的正路；--force 的边界（接 rebase 危险面）。

07多人协作流整合

✓ 90%

「独占未推 → rebase 整理；共享已推 → merge」口诀的实战落地。
