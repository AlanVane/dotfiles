🏆 本课最大亮点

复习先行，旧账三清：开课前 5 组复习债全清——复发三次的 「rebase 原样搬运」误解**连胜 2/2 正式销账**；急救箱「对象库彻底消失」 resolved；「收尾混入」低载首过；merge 快进条件实测翻案自纠。
误解双破案：「pull = 更新工作目录」（文件拷贝模型）与 「push 被拒 = 裁决现场」（两类故障混淆）——均由**他自己的押注** 与现场实测当场击穿，当日立案当日结案。
彩蛋自发现：pull.rebase=true 是自己 dotfiles 的配置—— 「收尾跟整合方式走，不是写死 merge」由现场倒逼推导而出， 当天上午刚复习的 rebase 两态规则原地兑现。

⚠️ 记档弱点

收尾混入第 4 次复发：综合现场、提示原文就在屏上， 仍写出 merge --continue（对照原文自纠后，又过度纠正成 rebase 完成后继续 continue）。→ 对策升级：停车第一件事 = 逐字读 git 提示，命令以提示为准，不调记忆。
疲劳效应：押注纪律在长会话尾段崩塌（整段跳过 ×3、 标签代答）。教法侧同步记档：一次只问一步。

📖 带走的口诀

origin/main = 上次通讯的**快照**，只有你 fetch/pull/push 才刷新
pull = fetch + 整合（方式跟 pull.rebase 配置走）
被拒 = 账不齐（快进校验），不是文件冲突 → pull 整合 → push
-u 记两格：哪个远程（origin）+ 哪条分支（refs/heads/xxx）
整理历史只在 push 之前；已推共享 → merge 只加不改，绝不 force
